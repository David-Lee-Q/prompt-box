# 用户指令记忆

本文件记录了用户的指令、偏好和教导，用于在未来的交互中提供参考。

## 格式

### 用户指令条目
用户指令条目应遵循以下格式：

[用户指令摘要]
- Date: [YYYY-MM-DD]
- Context: [提及的场景或时间]
- Instructions:
  - [用户教导或指示的内容，逐行描述]

### 项目知识条目
Agent 在任务执行过程中发现的条目应遵循以下格式：

[项目知识摘要]
- Date: [YYYY-MM-DD]
- Context: Agent 在执行 [具体任务描述] 时发现
- Category: [运维部署|构建方法|测试方法|排错调试|工作流协作|环境配置]
- Instructions:
  - [具体的知识点，逐行描述]

## 去重策略
- 添加新条目前，检查是否存在相似或相同的指令
- 若发现重复，跳过新条目或与已有条目合并
- 合并时，更新上下文或日期信息
- 这有助于避免冗余条目，保持记忆文件整洁

## 条目

[部署拓扑：同步后端 + 前端反代]
- Date: 2026-08-29
- Context: Agent 在执行「云端同步/备份跨设备」功能开发时发现
- Category: 运维部署
- Instructions:
  - 本项目为前端（Vite/React）+ 零依赖 Node 同步后端。启动命令 `npm run dev` 由 `scripts/dev.mjs` 同时拉起两个进程：同步后端 `server/index.mjs`（监听 127.0.0.1:3001）与 Vite 前端（监听 0.0.0.0:3000）。
  - 预览环境只暴露前端端口 3000；前端通过 `vite.config.ts` 的 `server.proxy` 将 `/api/sync` 反代到 127.0.0.1:3001（符合单端口预览约束）。后端不直接对外暴露。
  - 同步数据（用户账号 + 各用户数据快照）持久化在 `server/data/sync-data.json`，该目录已加入 .gitignore，属环境本地数据，随容器保留、不随代码提交。重建/迁移环境时需另行保留此文件以保留云端账号数据。

[稳定预览地址访问方式]
- Date: 2026-08-29
- Context: Agent 在执行「云端同步/备份跨设备」功能部署验证时发现
- Category: 排错调试
- Instructions:
  - 稳定预览地址 `https://code.cosmoplat.cn/api/v1/p/{taskId}/{port}` 必须以「不带末尾斜杠」的形式访问：无斜杠时平台返回 302 跳转到真实预览（200 正常）。
  - 若手动在末尾加了 `/`（如 `.../3000/`），平台 nginx 网关会返回 400「请求错误」。这不是应用问题，自动化校验脚本测试该地址时应使用不带斜杠的形式。

[同步服务排错与数据文件维护]
- Date: 2026-08-29
- Context: Agent 在排查「账号注册没有持久化」问题时发现
- Category: 排错调试
- Instructions:
  - 同步后端会对每个请求输出日志（格式 `[sync-server] <时间> <方法> <路径> -> <状态码> user=<用户名> <耗时>`），日志位于运行 `npm run dev` 的后台终端输出文件中。排查跨设备同步/登录问题时，先读该文件确认用户设备实际发出了哪些请求、返回了什么状态码。
  - 直接修改 `server/data/sync-data.json`（重置密码、清理测试账号等）前必须先停掉 dev 服务（kill 对应后台终端），修改完成后再重新 `npm run dev` 启动；不停服务时内存中的状态会在下次写入时覆盖文件里的修改。
