# CC Switch 竞品分析与差异化策略

> 分析日期：2026-06-06
> 目标：分析 CC Switch 的 Prompt 管理功能，明确借鉴点与差异化方向

---

## 一、CC Switch 是什么

CC Switch（`farion1231/cc-switch`，GitHub 75K+ stars）是一个**桌面端 AI CLI 工具配置管理中心**，基于 Tauri 2 + Rust 构建。

### 核心定位

> "Universal Remote for AI Coding Tools"

不是 Prompt 管理工具，而是**AI CLI 工具的配置管理层**。

### 覆盖范围

| 功能模块 | 说明 |
|---------|------|
| **Provider 管理** | 50+ 预设（Anthropic/OpenAI/Google/AWS Bedrock 等），一键切换 |
| **MCP 服务器管理** | 统一面板管理 4 个工具的 MCP 配置，双向同步 |
| **Prompts 管理** | 系统提示词预设（CLAUDE.md / AGENTS.md / GEMINI.md）|
| **Skills 管理** | 一键从 GitHub 安装/更新技能 |
| **本地代理** | 格式转换、自动故障转移、熔断器 |
| **用量追踪** | Token 消耗、成本趋势、请求日志 |
| **会话管理** | 跨工具浏览和恢复对话历史 |
| **云同步** | Dropbox/OneDrive/iCloud/WebDAV |

## 二、CC Switch 的 Prompts 管理功能详解

### 2.1 功能范围

CC Switch 的 Prompts 管理定位于**系统提示词预设管理**，而非用户提示词管理：

| 维度 | CC Switch 的 Prompts |
|------|-------------------|
| **管理对象** | 系统提示词（System Prompt），写入各工具的 `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` |
| **编辑方式** | Markdown 编辑器，语法高亮 + 实时预览 |
| **切换机制** | 激活/停用切换，同一时间只能激活一个预设 |
| **同步机制** | 跨工具同步：编辑后自动写入各工具的配置文件 |
| **备份保护** | Smart Backfill：切换预设前自动保存当前手动修改 |

### 2.2 Smart Backfill（智能回填）

这是 CC Switch 最有亮点的功能：

```
场景：用户直接在 CLI 中手动编辑了 CLAUDE.md
       ↓
CC Switch 检测到文件内容与数据库中的预设不一致
       ↓
自动将手动修改的内容保存到当前预设
       ↓
再切换到新的预设
       ↓
手动修改不会丢失
```

触发时机：
- 切换预设时：保存当前文件内容到当前预设
- 编辑当前预设时：从文件读取最新内容
- 首次启动时：自动导入现有文件内容

### 2.3 局限性

| 限制 | 说明 |
|------|------|
| **只能管理系统提示词** | 不涉及用户编写的 Prompt 内容 |
| **无版本管理** | 没有版本历史、版本对比、回滚机制 |
| **无版本号** | 不支持语义化版本号或任何版本标识 |
| **无模板变量** | 不支持 `{{变量}}` 语法 |
| **无 AI 优化** | 没有 Prompt 优化、生成、评分能力 |
| **无测试评估** | 没有测试面板、跨模型对比、效果评分 |
| **无搜索** | 不支持语义搜索或关键词搜索 |
| **无标签分类** | 没有标签系统、场景分类 |
| **无收藏/筛选** | 不支持收藏、按标签/时间筛选 |
| **单激活限制** | 同一时间只能有一个预设激活 |
| **无导出为 Agent 工具** | 不能导出为 function calling 格式 |

## 三、借鉴点：CC Switch 值得学习的做法

### 3.1 Smart Backfill（智能回填）

CC Switch 解决了"用户在外部修改了文件，工具不知道"的问题。

**我们的场景映射**：用户在 Prompt 编辑器中编辑内容，但没有保存。关闭页面时自动保存草稿（我们已经做了）。但可以借鉴的是：

```
借鉴：Prompt 保存时的冲突检测
- 如果用户在外部（如另一个标签页）修改了同一 Prompt
- 保存时检测内容冲突，提示用户选择：覆盖/保留/对比合并
```

### 3.2 跨工具同步

CC Switch 一个预设写到多个工具的配置文件中。

**我们的场景映射**：用户可能在多个场景下使用同一个 Prompt 模板。

```
借鉴：Prompt 的"多场景挂载"
- 一个 Prompt 可以同时关联到多个场景（而非当前的一对一归属）
- 修改 Prompt 内容，所有挂载场景同步更新
```

### 3.3 一键导入/导出（Deep Link）

CC Switch 支持 `ccswitch://` 协议分享预设。

```
借鉴：Prompt 的 Deep Link 分享
- 生成 ccswitch://import/prompt?data=<base64> 格式链接
- 点击即可导入完整 Prompt（含版本、标签、场景）
```

### 3.4 编辑器实时预览

CC Switch 的 Markdown 编辑器支持实时预览。

```
借鉴：我们的 CodeMirror 编辑器目前没有预览
- 可增加"编辑/预览"切换模式
- 预览渲染 Markdown 格式
```

### 3.5 整体架构思路

CC Switch 的价值在于**统一管理分散在不同工具中的配置**。

```
借鉴：统一 Prompt 资产管理的思路
- 用户在不同平台（Claude.ai, ChatGPT, API）都有 Prompt
- 我们的工具可以成为"统一 Prompt 资产管理中心"
- 这是 CC Switch"统一配置"思路在 Prompt 领域的映射
```

## 四、差异化：我们的核心优势

### 4.1 对比矩阵

| 维度 | CC Switch Prompts | AI Prompt Manager (我们的) |
|------|------------------|---------------------------|
| **管理对象** | 系统提示词（给 AI 看的） | 用户提示词（用户管理和使用的） |
| **版本管理** | ❌ 无 | ✅ 语义化版本号 + 版本历史 + diff |
| **版本回滚** | ❌ 无 | ✅ 一键回滚 |
| **版本保护** | ❌ 无 | ✅ 保护/删除/初始版本不可删 |
| **模板变量** | ❌ 无 | ✅ P0 规划的 `{{变量}}` 系统 |
| **AI 优化** | ❌ 无 | ✅ P0 规划的 AI 优化建议 |
| **AI 生成** | ❌ 无 | ✅ P1 规划的 AI 生成 Prompt |
| **效果评分** | ❌ 无 | ✅ P0 规划的 1-5 星评分 |
| **测试面板** | ❌ 无 | ✅ P0 规划的内置测试 |
| **跨模型对比** | ❌ 无 | ✅ P2 规划的并行多模型对比 |
| **阶段状态** | ❌ 单激活限制 | ✅ P1 规划的 draft→testing→stable |
| **语义搜索** | ❌ 无 | ✅ P2 规划的 AI 搜索增强 |
| **场景分类** | ❌ 无 | ✅ 三级资产（场景→提示词→版本）|
| **标签系统** | ❌ 无 | ✅ 标签 + 自动补全 |
| **收藏/筛选** | ❌ 无 | ✅ 收藏 + 标签/时间筛选 |
| **数据持久化** | SQLite 本地 | IndexedDB 浏览器内 |
| **导出 Agent 工具** | ❌ 无 | ✅ P2 规划的 4 种格式导出 |
| **离线可用** | 部分 | ✅ PWA 完全离线 |
| **自动保存草稿** | Backfill 被动 | ✅ 30s 主动自动保存 |
| **快照备份** | ❌ 无 | ✅ 每日自动快照（3 份）|
| **存储监控** | ❌ 无 | ✅ 用量监控 + 配额预警 |

### 4.2 核心差异

```
CC Switch                    AI Prompt Manager
─────────────────            ─────────────────
"基础设施层"                  "内容层"
管理 Provider / MCP / 配置    管理 Prompt 内容本身
面向工具                     面向人
系统提示词（给 AI 的指令）    用户提示词（人的资产）
无版本概念                    全生命周期版本管理
配置文件同步                  创作 + 优化 + 测试闭环
```

### 4.3 提炼为差异话术

> CC Switch 管的是"AI 工具的遥控器"，我们管的是"AI 提示词的资产"。
>
> CC Switch 解决的是"我有 5 个 AI 工具，配置太乱"的问题。
> 我们解决的是"我有 100 个 Prompt，哪个好用、怎么迭代、如何复用"的问题。

## 五、差异化竞争策略

### 5.1 明确不做的领域

不要试图和 CC Switch 竞争：

| 不要做 | 原因 |
|--------|------|
| Provider 管理 | CC Switch 50+ 预设 + 本地方案，耗时耗力 |
| MCP 服务器管理 | 需要后端基础设施，偏离前端定位 |
| 跨工具配置同步 | 需要深度集成各 CLI 工具，开发量大 |
| 用量追踪 | 需要本地代理拦截请求，架构复杂 |
| 本地代理/故障转移 | 这是基础设施层能力 |

### 5.2 强化自身优势

应该深化的差异化能力：

```
当前核心:  三级资产管理（场景→提示词→版本）
                  ↓
v2.0 核心:  内容创作 + 版本管理 + AI 优化 + 测试评估 闭环
                  ↓
远期方向:  个人 Prompt 全生命周期工作台
            ┌──────────────────────────┐
            │  创作:  AI 生成 + 优化     │
            │  管理:  分类 + 版本 + 标签  │
            │  评估:  测试 + 评分 + 对比  │
            │  使用:  变量填充 + Agent 导出│
            │  安全:  快照备份 + 导入导出  │
            └──────────────────────────┘
```

### 5.3 潜在的合作方向

CC Switch 和 AI Prompt Manager 实际上是互补关系：

```
CC Switch（配置层）          AI Prompt Manager（内容层）
     │                              │
     │  Provider 切换                │  编写/管理/优化 Prompt
     │  MCP 管理                     │  版本迭代 + 效果评估
     │  系统提示词同步               │  模板变量 + Agent 导出
     │  用量追踪                     │  快照备份 + 导入导出
     │                              │
     └──────────┬───────────┘        └──────┬────────────┘
                │                          │
                ▼                          ▼
      AI 开发者的完整工具链
      Provider → 配置 → Prompt → 执行 → 评估
```

未来可以考虑的集成点：

1. **AI Prompt Manager 导出 Prompt → CC Switch 导入为系统提示词**
2. **CC Switch Provider 切换 → AI Prompt Manager 自动切换测试模型**
3. **CC Switch 用量数据 → AI Prompt Manager 的成本分析**

## 六、结论

### 需要借鉴的功能

| 借鉴点 | 优先级 | 是否已规划 |
|--------|--------|-----------|
| Smart Backfill（保存冲突检测） | P1 | 未规划，建议加入 v2.x |
| 多场景挂载（一个 Prompt 归属多个场景）| P2 | 未规划，建议加入 v2.x |
| Deep Link 分享 | P3 | 未规划 |
| 编辑器预览模式 | P2 | 未规划 |

### 不需要做的功能

| CC Switch 功能 | 不做的原因 |
|---------------|-----------|
| Provider 管理 | 偏离定位，且已有成熟方案 |
| MCP 服务器 | 需要后端，偏离纯前端定位 |
| 用量追踪 | 需要的用户少，开发成本高 |
| 本地代理 | 架构复杂，安全风险高 |

### 核心结论

```
CC Switch 不是竞品，是互补品。

它们解决不同层面的问题：
- CC Switch 解决 "如何连接 AI 工具"
- 我们解决 "如何写好 AI 提示词"

两者可以共存，甚至可以集成。
```
