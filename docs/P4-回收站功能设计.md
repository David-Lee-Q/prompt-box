# P4：回收站功能设计

> 日期: 2026-06-13 | 状态: 待评审

---

## 一、目标

将删除操作从硬删除改为软删除：提示词和场景删除后进入回收站，30 天内可恢复，超期自动清理。

---

## 二、数据模型

### 方案：软删除字段

在现有表上加 `deletedAt?: number` 字段。`null` = 正常，有值 = 已删除（值为时间戳）。

```ts
// types/index.ts
interface Scene {
  // ... 现有字段
  deletedAt?: number;
}

interface Prompt {
  // ... 现有字段
  deletedAt?: number;
}

// Version 不单独标记——跟随其 prompt。prompt 恢复时版本自动恢复。
```

### Dexie Schema 升级

```ts
// db/index.ts — db.version(4)
db.version(4).stores({
  scenes: 'id, name, sortOrder, createdAt, deletedAt',
  prompts: 'id, sceneId, name, *tags, isStarred, createdAt, updatedAt, deletedAt',
  versions: 'id, promptId, version, score, createdAt',
});

// 为 deletedAt 建索引，查询可高效过滤
```

### 查询变更

所有列表查询追加过滤：

```ts
// 之前
db.prompts.where('sceneId').equals(id).toArray()
// 之后
db.prompts.where('[sceneId+deletedAt]').equals([id, null]).toArray()
```

Dexie 不直接支持复合条件，改为在内存过滤：

```ts
const all = await db.prompts.where('sceneId').equals(id).toArray();
const active = all.filter(p => p.deletedAt == null);
```

或者使用 `db.prompts.filter(p => p.sceneId === id && p.deletedAt == null)`。

## 五、交互细节

| 场景 | 行为 |
|------|------|
| 删除场景 | 场景 + 其下所有 prompt 同时标记 `deletedAt` |
| 恢复场景 | 场景 + 其下所有 prompt 同时清除 `deletedAt` |
| 恢复提示词 | 若其场景也在回收站→仅恢复 prompt，场景保持删除 |
| 搜索/筛选 | 不搜回收站内容 |
| 导出 | 不含已删除项 |
| 快照 | 含已删除项（用于恢复） |
| 清空回收站 | 永久删除所有软删除项（含场景和提示词） |

## 七、技术细节

### 7.1 索引查询效率

Dexie 不支持复合条件 `[sceneId + deletedAt]`，采用两步查询：

```ts
const all = await db.prompts.where('sceneId').equals(id).toArray();
return all.filter(p => p.deletedAt == null);
```

软删除数据量通常远小于活跃数据（<20%），内存过滤开销可忽略。

### 7.2 自动清理

StatusBar 挂载时检查：

```ts
const cutoff = Date.now() - 30 * 24 * 3600 * 1000;
const expired = await db.prompts.where('deletedAt').below(cutoff).toArray();
for (const p of expired) await permanentDeletePrompt(p.id);
```

或仅在打开回收站时触发，避免每次打开页面都扫描。

## 八、投入/收益/风险评估

| 维度 | 评估 | 说明 |
|------|------|------|
| **投入** | 中（约 4-6h） | 10 个文件，核心改动在 Service 层和新增 TrashPage |
| **收益** | 高 | 用户误删后无需导入备份即可恢复 |
| **影响** | 中 | 所有查询需要加 `deletedAt == null` 过滤，漏一处就显示已删除数据 |
| **风险** | 中 | 软删除后存储量增加（旧数据不释放），30天后自动清理兜底 |
| **兼容性** | 低风险 | v3→v4 升级，旧数据无 `deletedAt` 字段（`undefined == null` 为 true，天然过滤正确） |

### 主要风险

1. **查询遗漏** — 某处查询忘记加过滤，导致回收站数据出现在正常列表中。需​​全量审计所有查询点。
2. **Storage 增加** — 用户大量删除后数据未释放。30天自动清理缓解此问题。
3. **导出导入** — 导入含 `deletedAt` 的数据时需决策：保留删除状态还是自动恢复。

---

## 九、建议

1. **先做提示词回收站**，场景回收站延后（场景删除本来就有确认弹窗，误删概率低）
2. **自动清理周期** 默认 30 天，可在设置中调整
3. **回收站独立路由** `#/trash`，不污染主列表
