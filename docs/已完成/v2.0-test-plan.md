## 2. 测试环境

### 2.1 技术栈

| 层次 | 工具 |
|------|------|
| 单元测试 | Vitest |
| UI 组件测试 | @testing-library/react（预留） |
| E2E 测试 | Playwright |
| 类型检查 | TypeScript `tsc --noEmit` |
| 构建验证 | Vite `vite build` |

### 2.2 运行命令

```bash
# 安装依赖
pnpm install

# 类型检查
npx tsc --noEmit

# 单元测试
npx vitest run

# 单元测试（watch 模式）
npx vitest

# E2E 测试（Mock 模式 — CI 推荐）
MOCK_AI=true npx playwright test

# E2E 测试（真实 API — 需要配置环境变量）
OPENAI_API_KEY=sk-xxx npx playwright test --grep "@real-api"

# E2E 测试（单文件）
npx playwright test tests/v2-quality-analysis.spec.ts

# 构建验证
npx vite build

# 开发服务器（手动测试用）
npx vite --host
```

### 2.3 AI Mock 策略

涉及 AI API 调用的测试使用 Playwright `page.route()` 拦截网络请求，返回预设 JSON 响应。

**Mock 模式（默认，CI 使用）：**
- 环境变量 `MOCK_AI=true` 或默认行为
- 拦截 `/v1/chat/completions` 和 `/v1/messages`
- 返回预设的高质量优化/生成/测试结果
- 网络故障测试单独拦截并返回 429/500/超时

**真实 API 模式（手动验证用）：**
- 设置 `OPENAI_API_KEY` 或 `ANTHROPIC_API_KEY` 环境变量
- 使用 `@real-api` 标签筛选
- 仅在开发机手动执行

**Mock 响应示例：**
```json
{
  "choices": [{
    "delta": { "content": "优化后的提示词内容..." },
    "message": { "content": "优化后的提示词内容..." }
  }]
}
```

### 2.4 测试数据准备

- IndexedDB 每次测试前清空（Playwright 通过 `page.evaluate` 删除数据库）
- AI 设置通过 localStorage 预设或 UI 操作配置
- 测试用 API Key 从环境变量读取（CI）或使用 Mock
