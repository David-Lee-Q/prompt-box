# P1-1：类型感知的变量输入控件

> 2026-06-09

## Context

当前变量系统只支持纯文本输入。同一个提示词模板中，变量 `{{目标语言}}` 用户可能手打 "英文"/"英语"/"English"/"en"，不一致的输入导致 AI 输出质量波动。类型感知变量通过给每个变量绑定元数据（类型+选项+校验），让填写从"手打一切"变成"选填结合"。

## 现状追踪

### 当前实现

```

  正则: /{{(\w+)}}/g                          — 只提取变量名，丢弃类型信息
```

### 关键调用链

```
PromptEditor 输入 {{变量名}} → extractVariables() → promptService 存储
→ useVariables() → VariableForm 渲染 → renderTemplate() 替换
```

## 目标行为

用户可以在提示词内容中用内联语法声明变量类型：

```
{{变量名:类型:选项}}
```

示例：
```
你是专业翻译。将以下文本翻译成{{目标语言:select:英文,日文,法文,德文}}。
语气风格：{{语气:select:正式,随意,商务,学术}}
字数限制：不超过{{最大字数:number:50,5000}}字
是否解释理由：{{显示理由:boolean}}
原文：
{{原文:textarea}}
```

系统自动解析类型，在填写时为每种类型渲染对应控件。

> **评审修订 (2026-06-09)**：修正 renderTemplate 正则兼容、中文变量名支持、Boolean 默认行为

## 实现方案

### 1. 语法设计

**变量名编码约定**：变量名建议使用英文/数字/下划线（`\w+`），中文变量名通过 Unicode 属性 `[\p{L}\p{N}_]+` 支持。

```
{{name}}              → type='text'    (默认，向后兼容)
{{name:text}}         → type='text'    (单行输入)
{{name:textarea}}     → type='textarea'(多行输入)
{{name:number}}       → type='number'  (数字输入)
{{name:number:50,5000}} → type='number', min=50, max=5000
{{name:boolean}}      → type='boolean' (开关)
{{name:select:a,b,c}} → type='select', options=['a','b','c']
```

### 2. 类型定义新增

**`src/types/index.ts`** — Prompt 的 variables 字段从 `string[]` 升级为结构化类型：

```ts
export interface VariableDef {
  name: string;
  type: 'text' | 'textarea' | 'number' | 'boolean' | 'select';
  options?: string[];      // select 类型的候选项
  min?: number;            // number 类型的最小值
  max?: number;            // number 类型的最大值
  defaultValue?: string;
}

// Prompt 接口变更
export interface Prompt {
  // ... 其他不变
  variables?: VariableDef[];  // 原 string[]
}
```

**`src/hooks/useVariables.ts`** — VariableInfo 扩展：

```ts
export interface VariableInfo {
  name: string;
  value: string;
  type: 'text' | 'textarea' | 'number' | 'boolean' | 'select';
  options?: string[];
  min?: number;
  max?: number;
}
```

### 3. 解析器重写

**`src/utils/variables.ts`** — `extractVariables()` 替换：

```ts
const VAR_RE = /\{\{(\w+)(?::(\w+))?(?::([^}]+))?\}\}/g;

export function extractVariables(content: string): VariableDef[] {
  const seen = new Set<string>();
  const vars: VariableDef[] = [];
  for (const m of content.matchAll(VAR_RE)) {
    const name = m[1];
    if (seen.has(name)) continue;
    seen.add(name);
    const type = (m[2] || 'text') as VariableDef['type'];
    const opts = m[3];
    const def: VariableDef = { name, type };
    if (type === 'number' && opts) {
      const [min, max] = opts.split(',').map(Number);
      if (!isNaN(min)) def.min = min;
      if (!isNaN(max)) def.max = max;
    } else if (type === 'select' && opts) {
      def.options = opts.split(',').map((s) => s.trim());
    }
    vars.push(def);
  }
  return vars;
}
```

保留向后兼容：不含类型的 `{{name}}` 照样工作，默认 `type='text'`。

### 4. VariableForm 条件渲染

**`src/components/ai/VariableForm.tsx`** — 核心改动。`variables.map()` 根据 `v.type` 渲染不同控件：

| 类型 | 渲染控件 | 备注 |
|------|---------|------|
| `text` | `<Input>` | 当前行为 |
| `textarea` | `<Textarea rows={3}>` | 多行 |
| `number` | `<Input type="number" min={v.min} max={v.max}>` | 带校验 |
| `boolean` | Switch 开关 | 值为 `"true"/"false"` |
| `select` | `<select>` 原生下拉 | 选项列表 |

### 5. 持久化

**`src/services/promptService.ts`** — `savePrompt` 中调用升级后的 `extractVariables()`，返回 `VariableDef[]`，存入 DB 的 `variables` 字段。Dexie 自动适应 JSON 结构变化，无需 schema 迁移。

### 6. 向后兼容

- 旧提示词的 `variables: string[]` 格式：在读取时做兼容转换
- 旧 `{{name}}` 语法（无类型）自动识别为 `type='text'`

## 评审发现与修订 (2026-06-09)

### 1. renderTemplate 正则必须兼容新语法（阻断）

**问题**：`renderTemplate()` 当前用 `\{\{name\}\}` 匹配，新语法 `{{lang:select:EN,JP}}` 不会被匹配。

**修正**：`src/hooks/useVariables.ts` 的替换正则由 `\{\{${name}\}\}` 改为 `\{\{${name}(:[^}]*)?\}\}`，匹配 name 后的可选 `:type:opts` 后缀。

### 2. \w+ 不支持中文变量名

**问题**：文档示例使用了 `{{目标语言:select:...}}`，但 `\w+` 只匹配 `[a-zA-Z0-9_]`。

**修正**：变量名正则改为 `[\p{L}\p{N}_]+` 加 `u` 标志以支持 Unicode；或文档中明确要求变量名只用英文（推荐后者，与大多数编程实践一致）。

### 3. Boolean 未选择时的行为

**问题**：未触碰的 boolean 开关值为空字符串，`renderTemplate` 的 `v.value || "{{name}}"` 会保留占位符，而已切换为 false 的会替换为 "false"。

**修正（设计决策）**：boolean 变量默认值为 `undefined`（Switch 三态：未操作/true/false）。`renderTemplate` 中 boolean 值为空时保留占位符，非空时输出 "true" 或 "false"。变量面板的 Switch 初始状态为未操作（不显示为开或关），用户必须主动选择。

### 4. 变量重复定义：首次获胜

**问题**：用户写 `{{name:text}}` 和 `{{name:number:1,100}}` 时只有第一个被保留。

**修正**：`extractVariables` 去重保持首次获胜。用 console.warn 提示重复定义。

### 5. 旧 DB 数据兼容

**问题**：旧提示词的 `variables: string[]` 与新代码期望的 `VariableDef[]` 不兼容。当前该字段实际未被任何组件读取，但未来读取时需转换。

**修正**：在 `promptService.get()` 返回前做兼容转换：
```ts
if (prompt.variables?.length && typeof prompt.variables[0] === 'string') {
  prompt.variables = (prompt.variables as string[]).map(name => ({ name, type: 'text' as const }));
}
```
