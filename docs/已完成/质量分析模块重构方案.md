     质量分析模块重构方案

     Context

     当前质量分析模块有 3 个核心问题：
     1. Token 估算无意义：跨模型对比几百 token 的成本差异是千分之一美元级别，对用户无决策价值
     2. 维度单一：只有清晰度、结构、冗余三个维度，缺少具体性、可操作性、安全性等更具参考价值的评估
     3. Token 估算不准确：中英文用统一比率，中文实际 token 消耗被低估约 2 倍

     目标

     将质量分析从"打分工具"升级为"诊断 + 优化建议工具"——不仅告诉用户哪里不好，还给出具体优化方向。

     ---
     新版维度设计

     维度 1：Token 效率（替代当前 Token 估算）

     不做跨模型对比，改为"瘦身空间"分析：

     ┌──────────────┬──────────────────────────────────────────────────────────────────────────────────────┐
     │    检测项    │                                         说明                                         │
     ├──────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
     │ 语言混合检测 │ 统计中文字符占比，按中英文分别估算（中文 1.6~2.2 chars/tok，英文 3.2~3.7 chars/tok） │
     ├──────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
     │ 冗余行检测   │ 保留现有逻辑，提高检测精度（>30 字符的重复行）                                       │
     ├──────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
     │ 啰嗦短语     │ 匹配 "in order to" → "to"、"please kindly" 等 10+ 模式，给出替换建议和节省 token 数  │
     ├──────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
     │ 礼貌用语膨胀 │ 统计 "please"、"thank you"、"kindly" 等在系统指令中无意义的词                        │
     ├──────────────┼──────────────────────────────────────────────────────────────────────────────────────┤
     │ 压缩率       │ 综合计算可节省 token 占比（%）                                                       │
     └──────────────┴──────────────────────────────────────────────────────────────────────────────────────┘

     输出：单一估算值（~X tok）+ 可优化空间（可节省 Y tok，Z%）

     维度 2：具体性

     ┌──────────────┬────────────────────────────────────────────────────────────────────────────────┐
     │    检测项    │                                      说明                                      │
     ├──────────────┼────────────────────────────────────────────────────────────────────────────────┤
     │ 输出格式指定 │ 是否包含 JSON/表格/YAML/Markdown + 输出/返回/格式 关键词                       │
     ├──────────────┼────────────────────────────────────────────────────────────────────────────────┤
     │ 约束明确度   │ 是否包含数量、范围、禁止项等约束词（必须、不要、禁止、限制、范围等）           │
     ├──────────────┼────────────────────────────────────────────────────────────────────────────────┤
     │ 角色定义     │ 是否定义了 AI 角色/视角（"你是一个…"、"作为…"、"act as…"）                     │
     ├──────────────┼────────────────────────────────────────────────────────────────────────────────┤
     │ 边界条件     │ 是否覆盖异常情况、错误处理（"如果…则…"、"当…时"）                              │
     ├──────────────┼────────────────────────────────────────────────────────────────────────────────┤
     │ 模糊词检测   │ 扩展原有 6 个正则为 15+ 个，覆盖英文+中文（stuff、things、"做好"、"弄一下"等） │
     └──────────────┴────────────────────────────────────────────────────────────────────────────────┘

     维度 3：可操作性

     ┌──────────────┬─────────────────────────────────────────────────────────────────────────────────┐
     │    检测项    │                                      说明                                       │
     ├──────────────┼─────────────────────────────────────────────────────────────────────────────────┤
     │ 指令词密度   │ 统计 "分析/返回/列出/生成/执行/检查" 等强动词 vs "考虑/尝试/建议/可能" 等弱动词 │
     ├──────────────┼─────────────────────────────────────────────────────────────────────────────────┤
     │ 弱动词标记   │ 列出所有弱动词位置和替换建议                                                    │
     ├──────────────┼─────────────────────────────────────────────────────────────────────────────────┤
     │ 步骤清晰度   │ 是否包含编号步骤或分阶段指令                                                    │
     ├──────────────┼─────────────────────────────────────────────────────────────────────────────────┤
     │ 输入输出分离 │ 是否有明确的输入/输出界定                                                       │
     └──────────────┴─────────────────────────────────────────────────────────────────────────────────┘

     维度 4：可读性

     ┌───────────────┬───────────────────────────────────────┐
     │    检测项     │                 说明                  │
     ├───────────────┼───────────────────────────────────────┤
     │ 结构完整性    │ 标题层级、段落划分（保留现有逻辑）    │
     ├───────────────┼───────────────────────────────────────┤
     │ 句子长度      │ 标记超过 40 词的长句                  │
     ├───────────────┼───────────────────────────────────────┤
     │ Few-shot 质量 │ 示例数量 + 是否包含 Input/Output 配对 │
     ├───────────────┼───────────────────────────────────────┤
     │ 信息密度      │ token 数 vs 独立约束/要求数量         │
     └───────────────┴───────────────────────────────────────┘

     维度 5：安全性（P2）

     ┌──────────┬────────────────────────────────────────────────────┐
     │  检测项  │                        说明                        │
     ├──────────┼────────────────────────────────────────────────────┤
     │ 注入检测 │ 匹配 "ignore previous instructions"、"system:"、"< │
     ├──────────┼────────────────────────────────────────────────────┤
     │ PII 检测 │ 邮箱、手机号、身份证号、IP 地址等正则              │
     └──────────┴────────────────────────────────────────────────────┘

     ---
     综合评分权重

     加权分 = 具体性×0.30 + 可操作性×0.25 + Token效率×0.20 + 可读性×0.15 + 安全性×0.10

     ---
     文件变更清单

     1. src/services/promptAnalyzer.ts — 重写

     保留：analyzePrompt() 函数签名不变（入参 content: string，出参 AnalysisReport）

     新增：
     - detectLanguageMix() — 返回 cjkRatio
     - estimateTokensSmart() — 语言感知 token 估算，返回单一数字
     - detectVerbosePhrases() — 啰嗦短语匹配，返回 {text, suggestion, savedTokens}[]
     - analyzeSpecificity() — 替代原 analyzeClarity，包含模糊词+格式+约束+角色
     - analyzeActionability() — 新增，弱动词检测+指令密度+步骤清晰度
     - analyzeTokenEfficiency() — 替代原 estimateTokens+analyzeRedundancy
     - analyzeReadability() — 替代原 analyzeStructure，新增句子长度
     - analyzeSecurity() — 新增，注入+PII 检测

     类型变更：AnalysisReport 结构变化，删除 TokenEstimate，新增 TokenEfficiency、Specificity、Actionability、Readability、Security

     2. src/components/ai/QualityAnalysisPanel.tsx — 重写 UI

     - 5 个维度卡片，每个维度显示分数 + 进度条 + 折叠详情
     - Token 效率卡片显示：估算 token 数 + 可压缩比例 + 具体啰嗦短语列表
     - 具体性卡片显示：格式/约束/角色/边界 各项是否通过 + 模糊词列表
     - 可操作性卡片显示：强弱动词比例 + 弱动词列表
     - 建议区合并为底部优先建议列表（标记 High/Medium/Low）
     - 顶部保留综合评分大数字

     3. src/pages/PromptDetailPage.tsx — 小改

     - 删除 analysisReport 状态初始化对 AnalysisReport 类型的依赖（类型变了）
     - 工具栏按钮处的内联评分徽章改用 QualityAnalysisBadge 组件
     - 其余逻辑不变（两个 analyzePrompt 调用点不变）

     4. src/components/ai/QualityAnalysisBadge.tsx — 复用

     当前是孤儿组件，PromptDetailPage 应改用它来渲染工具栏评分徽章。

     ---
     不变的部分

     - analyzePrompt() 函数名和签名不变
     - PromptDetailPage 中的调用方式不变
     - QualityAnalysisPanel 的 props 接口不变（report + onRefresh + onClose）
     - 面板的开关逻辑不变

     ---
     验证计划

     1. 在已有 Prompt 详情页打开质量分析面板，验证 5 个维度卡片均正常渲染
     2. 用中文为主的 prompt 测试，验证 token 估算比之前更准确（中文混合比率生效）
     3. 修改 prompt 内容后点击刷新，验证重新分析
     4. 无内容 prompt → 面板显示空状态 + "开始分析"按钮
     5. 检查 toolbar 上的评分徽章是否正确使用 QualityAnalysisBadge 组件
