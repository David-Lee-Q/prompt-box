# P0 三个功能详细设计

> 2026-06-09 | 已通过专家评审，评审发现已整合到各方案中

## Context

三个 P0 功能均为现有的改进增强，不改架构：
1. **版本历史浏览** — 已有 `VersionList` 组件和版本数据，但只能看列表不能预览内容
2. **think 块过滤** — DeepSeek R1 等模型输出 `<\think>...响应` 标签，目前直接混入结果
3. **AI 快速调优预设** — OptimizePanel 只有手动分析维度 + 自由文本，缺少一键快捷操作

## P0-1：版本历史 — 点击卡片预览内容

### 现状追踪

```
用户点击"版本历史" → showVersions=true → 右侧面板渲染 <VersionList>
  VersionList 当前能力:
    - 调用 getVersionsByPrompt(promptId) 获取版本列表
    - 渲染每个版本的卡片（版本号、评分、日期、changeLog）
    - 高亮 currentVersionId 版本（蓝色边框 + "当前"徽章）
    - 每个卡片底部有回滚/保护/删除按钮
    - props: promptId, currentVersionId, onRollback, onDelete, onToggleProtection, onClose
    - 缺失: 卡片不可点击，无选中状态，无内容预览

左侧始终显示 <PromptEditor>（可编辑当前提示词）
  PromptEditor props: prompt (当前 Prompt 对象), sceneId, onBack, onSaved

PromptEditor 内部状态机（关键——只读模式必须处理这 5 条写入路径）:
  1. useEffect([prompt, sceneId]): content 从 prompt.content 初始化，同时检查 localStorage 草稿恢复
  2. saveDraft (useRef): 比较 content vs prompt.content，差异时写 localStorage
  3. auto-save timer (30s 定时器): 周期调用 saveDraft
  4. beforeunload handler: 页面关闭时调用 saveDraft
  5. useKeyboardShortcuts: Ctrl+S → handleSave, Ctrl+I → 打开优化面板
```

### 目标行为

1. 点击版本卡片 → 该卡片高亮（不同于"当前"的蓝色边框，用选中态样式）
2. 左侧编辑器**切换为只读预览**，显示选中版本的内容
3. 点击"返回当前版本" → 恢复编辑器正常模式
4. 关闭版本面板 → 自动恢复编辑器
5. 删除正在预览的版本 → 自动回到当前版本编辑模式

### 实现方案（评审后修订版）

**核心策略：用一个 `isReadonly: boolean` 守卫，短路所有写入路径。**

#### PromptEditor 改动 (`src/components/prompt/PromptEditor.tsx`)

```ts
// 新增 props
interface PromptEditorProps {
  // ... 现有 props
  readOnly?: boolean;              // 是否只读模式
  readOnlyContent?: string;        // 只读时显示的内容
  readOnlyTitle?: string;          // 只读时的提示标题（如 "v1.3"）
  onBackToCurrent?: () => void;    // 返回当前版本的回调
}
```

**只读模式下的行为变更：**

1. **内容初始化**：新增独立 `useEffect`，当 `readOnly && readOnlyContent` 时直接 `setContent(readOnlyContent)`，不检查 localStorage 草稿。当 `readOnly` 变为 false 时恢复 prompt.content。
2. **saveDraft 短路**：函数开头加 `if (readOnly) return;`
3. **auto-save timer 短路**：`useEffect` 中 `if (!draftKey || readOnly) return;`
4. **beforeunload 短路**：`handleBeforeUnload` 中 `if (readOnly) return;`
5. **Ctrl+S 短路**：`useKeyboardShortcuts` 中 `'Ctrl+S': readOnly ? undefined : handleSave`
6. **Ctrl+I 短路**：同样改为条件注册
7. **UI 隐藏**：保存按钮、AI优化按钮、生成按钮、VariableForm、TagInput、notes、changeLog 全部不渲染
8. **CodeMirror**：`readOnly={readOnly}` + `basicSetup` 中禁用 `highlightActiveLine`
9. **提示条**：编辑器顶部显示 `正在浏览版本 {readOnlyTitle} — ` + 返回按钮

#### VersionList 改动 (`src/components/version/VersionList.tsx`)

```ts
// 新增 props
interface VersionListProps {
  // ... 现有 props
  selectedVersionId: string | null;                        // 选中的版本 ID
  onSelect: (version: Version) => void;                     // 选中回调

```

- 卡片 `onClick={() => onSelect(v)}` + `cursor-pointer`
- 选中态样式: `border-primary/70 bg-primary/10 ring-1 ring-primary/30`
  （区别于"当前"的 `border-primary bg-primary/5`）
- "当前"徽章和选中态可共存

- `handleSelectVersion(version)`: `setViewingVersion(version)`


### 边界情况覆盖

| 场景 | 处理 |
|------|------|
| 只读模式下 Ctrl+S | 快捷键不注册 |
| 只读模式下 30s 自动存草稿 | 定时器不启动 |
| 只读模式下关闭标签页 | beforeunload 不写草稿 |

## P0-2：think 块过滤

### 现状追踪

```
模型响应流:
  OpenAIProvider.streamChat()    — openai.ts:32-53  逐 chunk 累积到 fullText, 调 onChunk(chunk)
  OpenAIProvider.chat()          — openai.ts:55-70  直接返回 response...content
  AnthropicProvider.streamChat() — anthropic.ts:43-76  stream.on('text', ...)
  AnthropicProvider.chat()       — anthropic.ts:78-101  返回 text block

调用方:
  optimizePrompt() — ai/index.ts:33-71  调 provider.streamChat (或 .chat 无 onChunk 时)
  generatePrompt() — ai/index.ts:73-96  调 provider.streamChat (或 .chat)
  TestPanel        — 直接调 provider.streamChat
  MultiModelTest   — 直接调 provider.streamChat
  GenerateDialog   — 调 generateCandidates() → provider.chat
```

### 需要过滤的标签

DeepSeek R1 使用反斜杠格式 `<\think>...响应`，其他模型使用标准 XML 格式：

```
<\think>...响应          ← DeepSeek R1（反斜杠 + 单独闭合标签）
<thinking>...</thinking>  ← 通用 thinking 块
<think>...</think>        ← 简化 think 块
[THINKING]...[/THINKING]  ← 方括号变体
【思考】...【/思考】        ← 中文全角变体
```

### 实现方案

**新增工具模块** `src/services/ai/thinkFilter.ts`：

```ts
const THINK_BLOCK_RE: RegExp[] = [
  // DeepSeek R1 格式（反斜杠标签）—— 必须排在前面
  /<\\think>[\s\S]*?<\\/think>/gi,
  // 标准 XML 格式（容忍开标签带属性如 <thinking duration="5s">）
  /<thinking\b[^>]*>[\s\S]*?<\/thinking>/gi,
  /<think\b[^>]*>[\s\S]*?<\/think>/gi,
  // 方括号变体
  /\[THINKING\][\s\S]*?\[\/THINKING\]/gi,
  // 中文全角变体
  /【思考】[\s\S]*?【\/思考】/gi,
];

export function stripThinkBlocks(text: string): string {
  let result = text;
  for (const re of THINK_BLOCK_RE) {
    result = result.replace(re, '');
  }
  return result.trim();
}
```

**集成策略：在两个 Provider 层过滤，不在 `ai/index.ts` 中过滤**（这样 TestPanel 和 MultiModelTest 的直接调用也能被覆盖）。

**流式显示权衡（明确记录）**：`stripThinkBlocks` 仅在最终 `fullText` 返回前调用。流式 `onChunk` 回调不做过滤。用户会在流式传输期间看到原始 think 标签闪烁，最终结果会被清理。实现流式过滤需要状态机，复杂度高（需处理标签跨 chunk 分割），当前阶段不实现。

两个 Provider 各改两处：
- `streamChat()`: `return fullText` → `return stripThinkBlocks(fullText)`
- `chat()`: `return ...content` → `return stripThinkBlocks(...content)`

### 已知限制

| 限制 | 说明 | 应对 |
|------|------|------|
| 流式期间可见原始标签 | onChunk 不过滤，用户看到 `<\think>` 闪烁 | 当前阶段接受。后续可升级为 StreamingThinkFilter |
| 误伤合法内容 | 教程类提示词输出中若含 think 标签示例会被删除 | 正则过滤的固有缺陷，概率极低 |
| Anthropic 扩展思考 | Anthropic 用独立 content block type（非内联文本），正则不适用 | 当前未启用扩展思考。启用时需改 `chat()` 遍历所有 content blocks |
| 嵌套 think 块 | 非贪婪匹配会留下残余闭合标签 | 无已知模型产生嵌套块，不做处理 |

### 文件变更

| 文件 | 改动 |
|------|------|
| `src/services/ai/thinkFilter.ts` | **新建** — `stripThinkBlocks()` 函数 |
| `src/services/ai/openai.ts` | import stripThinkBlocks；`streamChat` 和 `chat` 返回值前调用 |
| `src/services/ai/anthropic.ts` | 同上 |

### 验证

1. DeepSeek R1：运行测试 → `<\think>...响应` 不出现在结果中
2. 非思考模型（GPT、Claude）：确认正常文本不被误删
3. 四个场景全测：AI 优化、AI 生成、运行测试、模型对比
4. 分别测试流式（onChunk 路径）和非流式（chat 路径）

## P0-3：AI 快速调优预设菜单

### 现状追踪

```
OptimizePanel 四种 UI 状态:
  A. 未配置 API Key: 显示提示 + 前往设置按钮
  B. 初始态（无结果、非优化中）: 标题 + Textarea + 维度 chips + 按钮
  C. 优化中: 加载动画 + 流式结果 + [停止] 按钮
  D. 结果态: OptimizeDiff + [接受更改] [忽略]
  以及错误态（isOptimizing=false && error）

优化调用链:
  handleOptimize → optimizePrompt({ content, instruction, dimensions })
    → ai/index.ts:
        system prompt = 维度诊断 (system role)
        user message = 额外要求：${instruction} (user role)
    → provider.streamChat
```

### 评审发现与设计决策

**预设与维度重叠问题**：预设（如"更简洁"）与维度（如 tokenEfficiency）存在语义重叠，两者在系统中走不同通道——预设作为 user message，维度作为 system prompt。**决策：共存，不互斥。** 预设提供风格方向的自然语言指导，维度提供数据驱动的诊断发现。同时发送两者给 AI 是冗余但无害的——AI 可以自行整合。重叠对应关系见下表：

| 预设 | 可能重叠的维度 |
|------|-------------|
| 更简洁 | tokenEfficiency |
| 更具体 | specificity |
| 丰富约束 | specificity |
| 强化角色 | specificity |
| 优化结构 | readability |
| 提取变量 | 无直接重叠 |

**stale dims 问题**：`dims` 的 `useState` 初始化器只执行一次。如果 OptimizePanel 挂载期间 content 变化，dim 的 score/findings 会过时。**修复**：在 PromptEditor.tsx 中给 OptimizePanel 加 `key={content}`，content 变化时强制重建组件。

### 目标行为

在指令输入框上方增加一排预设快捷 chips：

| 预设 | 注入的 instruction 文本 |
|------|----------------------|
| 提取变量 | 请将提示词中可替换的关键信息点（如角色名、任务主题、输出主题等）用 {{变量名}} 格式替换，使提示词成为可复用的模板 |
| 更具体 | 请将模糊表述替换为明确、可量化的指令，每项要求都要有具体的判断标准 |
| 更简洁 | 请删除冗余措辞和礼貌用语，用最精简的语言表达相同的指令，压缩 Token 用量 |
| 丰富约束 | 请检查并补充缺失的约束条件（输出格式、字数限制、禁止项、边界情况处理） |
| 强化角色 | 请明确 AI 的角色定位、专业领域和输出视角，增强角色设定描述 |
| 优化结构 | 请用标题和编号重新组织结构，确保输入/输出界定清晰，任务步骤分明 |

### 实现方案

在 `OptimizePanel` 的初始态（状态 B）内部增加 preset chips：

```
┌─ "AI 优化" 标题
├─ 快捷预设（新）:
│  [提取变量] [更具体] [更简洁] [丰富约束] [强化角色] [优化结构]
│  首次点击任一 chip → 填入下方 Textarea，chip 高亮
│  再次点击同一 chip（已选中） → 取消选中，清空 Textarea
│  点击另一 chip → 替换 Textarea 内容，切换高亮
│  手动编辑 Textarea → 自动取消所有 chip 高亮（内容不一致检测）
├─ Textarea: 自由编辑
├─ 质量分析诊断维度 (不变)
├─ [开始优化] [取消]
└─ ...
```

**状态管理**：
- `activePreset: string | null` — 当前选中的预设名称
- chip 点击逻辑：如果 `activePreset === name` → 清空；否则 → 设置
- `onChange` 中：`if (e.target.value !== PRESETS.find(p => p.name === activePreset)?.text) setActivePreset(null)`

**已明确的边界行为**（评审补充）：用户选中预设 A，手动编辑文本 → activePreset 清空。此时再点预设 A chip → 会**重新填入原始预设文本，覆盖用户编辑**。这是设计选择（简单明了），不做二次确认弹窗。

**PromptEditor.tsx 配套改动**（修复 stale dims）：
```tsx
{showOptimize && (
  <OptimizePanel
    key={content}   // ← 加 key，content 变化时强制重建
    content={content}
    ...
  />
)}
```

### 文件变更

| 文件 | 改动 |
|------|------|
| `src/components/ai/OptimizePanel.tsx` | 新增 PRESETS 常量 + preset chips UI + `activePreset` state |
| `src/components/prompt/PromptEditor.tsx` | OptimizePanel 加 `key={content}` |

### 验证

1. 打开有内容的提示词 → 点击"AI 优化"
2. 点击预设 chip "[更简洁]" → Textarea 填入对应指令，chip 高亮
3. 再次点击 "[更简洁]" → Textarea 清空，chip 取消高亮
4. 点击 "[更具体]" → Textarea 替换为新指令，高亮切换
5. 手动编辑 Textarea → chip 高亮消失
6. 选中预设 + 勾选分析维度 → 开始优化 → system prompt 含维度诊断，user message 含预设指令
7. 不选任何预设、不填指令、不勾维度 → 开始优化 → 使用默认通用优化
8. 编辑提示词内容后 OptimizePanel 关闭再打开 → 维度分数基于最新内容（key 强制重建）
