### 核心逻辑

```typescript
const [description, setDescription] = useState('');
const [candidates, setCandidates] = useState<{ id: string; content: string; reason?: string }[]>([]);
const [isGenerating, setIsGenerating] = useState(false);
const [error, setError] = useState<string | null>(null);
const abortRef = useRef<AbortController | null>(null);

const handleGenerate = async () => {
  if (!description.trim()) return;
  setIsGenerating(true);
  setError(null);
  setCandidates([]);
  const controller = new AbortController();
  abortRef.current = controller;

  try {
    // 一次性生成多个候选方案（AI 返回用 --- 分隔）
    const result = await generateCandidates(description, controller.signal);

    // 解析候选：按 "方案" 或 "---" 分割
    const parts = parseCandidates(result);
    setCandidates(parts.map((content, i) => ({
      id: generateId(),
      content,
      reason: i === 0 ? '推荐方案' : undefined,
    })));
  } catch (err: any) {
    if (err.name !== 'AbortError') {
      setError(err.message || '生成失败');
    }
  } finally {
    setIsGenerating(false);
    abortRef.current = null;
  }
};
```

### AI Service 补充 — `src/services/ai/index.ts`

> **注意**：P0 Step 1 已实现 `generatePrompt(description, onChunk?, signal?)` 用于流式生成单个 Prompt。
> P1 需要的是"一次生成 2-3 个候选"的能力，应**新增** `generateCandidates` 而非覆盖已有函数。

```typescript
// 新增：生成多个候选 Prompt（非流式，一次返回多个）
export async function generateCandidates(
  description: string,
  signal?: AbortSignal
): Promise<string> {
  const provider = getCurrentProvider();
  if (!provider) throw new Error('AI 未配置，请在设置中配置 API Key');

  const systemPrompt = `你是一个 Prompt 生成专家。根据用户的需求描述，生成 2-3 个不同的 Prompt 候选方案。
每个方案之间用 "---" 分隔。
每个方案应包含完整的角色设定、任务描述、输出格式引导和约束条件。
确保方案之间有明显的差异（如不同的表达风格、不同的结构组织方式）。
直接返回 Prompt 内容，不要添加额外解释。`;

  return provider.chat(
    [
      { role: 'system', content: systemPrompt },
      { role: 'user', content: description },
    ],
    signal
  );
}

// 解析 AI 返回的候选方案
export function parseCandidates(text: string): string[] {
  // 按 --- 或 "方案" 分割
  const parts = text.split(/\n---\n|方案[ A-D][：:]\n?/).filter(Boolean);
  return parts.map((p) => p.trim()).filter((p) => p.length > 10);
}
```

### 采纳流程

用户点击候选下方的按钮后：

1. **采纳** → 对话框关闭，跳转到新建/编辑页并预设内容
2. **编辑后采纳** → 候选内容出现在可编辑的 textarea 中，用户修改后点"保存"触发采纳（满足"候选接近理想但需微调"的场景）
3. 如果当前在 Prompt 编辑页 → 替换编辑器内容，名称自动设为描述的前 N 字
4. 如果当前在 Prompt 列表页 → 跳转到该场景下的新建页面，预填内容

## Step 10：基于规则的标签建议

### 概述

保存 Prompt 时，从内容中提取高频关键词作为标签建议。**不调用 AI API**，纯前端规则匹配。轻量通知展示，用户可选应用或忽略。

> **降级原因**：个人用户 Prompt 库规模小（几十到几百条），用 AI 做标签推荐的延迟 + token 成本与其价值不成比例。基于关键词的规则匹配可覆盖 80% 场景，且零成本、即时响应。

### 标签建议 Service — `src/services/tagSuggest.ts`

```typescript
// 高频关键词映射：如果内容中包含这些词，建议对应标签
const KEYWORD_TAG_MAP: Record<string, string> = {
  '翻译': '翻译',
  'translate': '翻译',
  '文案': '营销文案',
  '营销': '营销文案',
  '广告': '营销文案',
  '代码': '代码',
  '编程': '代码',
  'code': '代码',
  '审查': '代码审查',
  'review': '代码审查',
  '客服': '客服',
  '用户': '客服',
  '邮件': '邮件',
  'email': '邮件',
  '摘要': '摘要',
  '总结': '摘要',
  'summarize': '摘要',
  '产品': '产品',
  'product': '产品',
  '写作': '写作',
  '文章': '写作',
  'writing': '写作',
  'JSON': '结构化输出',
  'JSON Schema': '结构化输出',
  'Markdown': '结构化输出',
  'API': 'API',
  'REST': 'API',
  '角色扮演': '角色扮演',
  'role': '角色扮演',
};

export interface TagSuggestion {
  tag: string;
  source: 'keyword' | 'existing';
}

export function suggestTags(
  content: string,
  existingTags: string[],
  existingAllTags: string[]
): TagSuggestion[] {
  const lower = content.toLowerCase();
  const suggestions: TagSuggestion[] = [];

  // 1. 关键字匹配
  for (const [keyword, tag] of Object.entries(KEYWORD_TAG_MAP)) {
    if (lower.includes(keyword.toLowerCase())) {
      suggestions.push({ tag, source: 'keyword' });
    }
  }

  // 2. 从已有标签库中找高频标签（内容中出现标签名本身）
  for (const tag of existingAllTags) {
    if (lower.includes(tag.toLowerCase())) {
      suggestions.push({ tag, source: 'existing' });
    }
  }

  // 去重 + 排除已有标签 + 排序（keyword 匹配优先）+ 限 5 个
  const seen = new Set(existingTags);
  return suggestions
    .filter((s) => !seen.has(s.tag) && seen.add(s.tag))
    .slice(0, 5);
}
```

### 防骚扰策略

| 条件 | 行为 |
|------|------|
| Prompt 已有 ≥3 个标签 | 不推荐 |
| 内容长度 < 50 字 | 不推荐（信息量不足）|
| 无关键字匹配 | 不推荐（没有建议可给）|
| 重复推荐（同一标签组合） | 不重复展示 |

| **总体建议** | Approve + 补充遗漏项 | 技术可行，关注组件膨胀 | **Adjust** — 精简 P1 范围 |

### 三位专家共识

**Step 9（AI 生成）是 P1 唯一高价值功能。** 三位专家一致认为"描述需求→AI 生成候选→采纳"解决了最高频的"冷启动"痛点，且复用 P0 Provider 基础设施，边际成本低。

**Step 8（阶段状态）应砍掉或延迟。** 理由汇总：

- P0 已有 1-5 星评分作为版本质量信号，status 与之概念重叠
- draft→testing→stable 三态流转是团队协作范式，个人用户感知不到价值
- 会增加 VersionList 卡片信息密度（P0 已有评分星标，P1 再加状态标签+切换按钮）
- 真正需要状态区分的是 v3 阶段的 Agent 发布场景
- 开发成本约 1 周，可重新分配到更有价值的事

**Step 10（自动标签）应降级。** 理由汇总：

- AI 调用延迟 + 复杂防骚扰策略的工程投入与感知价值不成比例
- 个人用户 Prompt 库规模小，基于关键词的规则匹配就能覆盖 80% 场景
- 可改为"保存时从内容中提取高频关键词作为标签建议"，省去 AI 调用

### 架构师特别关注的 5 个技术点

1. **Dexie 迁移**：无风险。v2→v3 纯增量，status 可选字段。存量 version 的 status 为 undefined，UI 需降级展示避免用户以为历史版本丢失。

2. **VersionList 膨胀**：当前卡片已有 3 badge + 3 按钮，P1 再加 1 badge + 3 按钮即达 4 badge + 4-5 按钮。如果再往里加功能应先拆分子组件。

3. **generatePrompt/generateCandidates 双函数**：合理，但 system prompt 文本重复。应抽取 `buildGenerationSystemPrompt()` 工具函数。

4. **标签推荐竞态**：`handleSave` 后 500ms setTimeout 回调可能在组件卸载后执行。需用 AbortController 或 mounted 检查。

5. **组件膨胀**：PromptDetailPage ~290行，PromptEditor ~350行。P1 建议各抽 `usePromptDetail` / `usePromptEditor` hook。

### 产品经理特别关注：功能叠加 vs 体验打磨

> P0 刚完成一个月，功能密度很高但几乎没有真实使用反馈窗口。当前工具面临的核心风险不是"功能不够"，而是 P0 的功能是否真正好用。在问题没被回答之前再堆 P1 功能，会让代码表面积膨胀而用户体验下降。
